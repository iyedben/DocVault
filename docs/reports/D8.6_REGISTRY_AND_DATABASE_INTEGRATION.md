## 2. Administrator Actions Executed Out-of-Band

In strict accordance with least privilege and separation of duties, all privileged infrastructure provisioning was executed out-of-band by the cluster administrator using `/home/docvault/.kube/config`, without granting `jenkins-deployer` any Secret read permissions:

### 2.1 Private Docker Hub Registry Secret & ServiceAccount
```bash
# 1. Create dockerconfigjson Secret from local Docker authentication
kubectl create secret generic docvault-registry-creds \
  --type=kubernetes.io/dockerconfigjson \
  --from-file=.dockerconfigjson=/home/docvault/.docker/config.json \
  --namespace=docvault

# 2. Apply approved application ServiceAccount with token automounting disabled
kubectl apply -f - <<EOF
apiVersion: v1
kind: ServiceAccount
metadata:
  name: docvault-app
  namespace: docvault
automountServiceAccountToken: false
imagePullSecrets:
  - name: docvault-registry-creds
EOF
```
*Security Impact:* Satisfies D8.3 Admission Policy Rule 9 (`serviceAccountName: docvault-app`, `automountServiceAccountToken: false`) and Rule 13 (Deployment template omits `imagePullSecrets`; Kubernetes SA admission controller injects pull secrets automatically at Pod creation).

### 2.2 PostgreSQL ClusterIP Service & Endpoints
```bash
kubectl apply -f - <<EOF
apiVersion: v1
kind: Service
metadata:
  name: docvault-postgres
  namespace: docvault
spec:
  type: ClusterIP
  ports:
    - name: postgres
      port: 5432
      targetPort: 5432
---
apiVersion: v1
kind: Endpoints
metadata:
  name: docvault-postgres
  namespace: docvault
subsets:
  - addresses:
      - ip: 172.18.0.2
    ports:
      - name: postgres
        port: 5432
EOF
```
*Security Impact:* Fully complies with all 5 D8.3 Service admission rules (Type `ClusterIP`, zero `externalIPs`, zero `nodePort`, zero `externalName`, zero `LoadBalancer` config). Routes pod traffic strictly to port 5432 on the host's isolated database container.

### 2.3 Application & Migrator Database Secrets
Two isolated database secrets were created from `.env` without logging credentials to console or disk:
```bash
# Application DML credential (docvault_app)
kubectl create secret generic docvault-app-db-creds \
  --from-literal=database-password="<POSTGRES_APP_PASSWORD>" \
  --namespace=docvault

# Migrator DDL credential (docvault_migrator)
kubectl create secret generic docvault-migration-db-creds \
  --from-literal=database-password="<POSTGRES_MIGRATION_PASSWORD>" \
  --namespace=docvault
```
*Security Impact:* Preserves role separation between runtime DML operations and schema DDL migrations. Secrets remain completely unreadable by `jenkins-deployer`.

### 2.4 Authorized Initial Alembic Schema Migration Job
Executed the initial schema migration using an authorized Kubernetes `batch/v1 Job` (`docvault-migrate-test`):
```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: docvault-migrate-init
  namespace: docvault
spec:
  template:
    spec:
      serviceAccountName: docvault-app
      automountServiceAccountToken: false
      restartPolicy: Never
      securityContext:
        runAsNonRoot: true
      containers:
        - name: migrator
          image: iyedbnaissa/docvault-api@sha256:05a3d9053c7250448b760e02f92422bb32c8a6b465c9222b858bfc8eb1ccd687
          command: ["alembic", "-c", "alembic.ini", "upgrade", "head"]
          env:
            - name: DATABASE_HOST
              value: docvault-postgres
            - name: DATABASE_PORT
              value: "5432"
            - name: DATABASE_NAME
              value: docvault
            - name: DATABASE_USER
              value: docvault_migrator
            - name: DATABASE_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: docvault-migration-db-creds
                  key: database-password
          securityContext:
            allowPrivilegeEscalation: false
            privileged: false
            readOnlyRootFilesystem: true
            capabilities:
              drop: ["ALL"]
```
*Result:* Job completed successfully with exit code 0. PostgreSQL schema verified at `version_num: 0002_documents`.

  (!has(c.env) || c.env.all(e,
    !has(e.valueFrom) || !has(e.valueFrom.secretKeyRef) ||
    (c.name == 'docvault' &&
     e.name == 'DATABASE_PASSWORD' &&
     e.valueFrom.secretKeyRef.name == 'docvault-app-db-creds' &&
     e.valueFrom.secretKeyRef.key == 'database-password')
