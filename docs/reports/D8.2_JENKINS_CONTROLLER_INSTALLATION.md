## 1. Executive Summary

Phase D8.2 implements the dedicated Jenkins Continuous Delivery (CD) controller for the DocVault project. Jenkins operates as an isolated, unprivileged, resource-capped container under Docker Compose on `docvault-srv`. 

The deployment strictly adheres to all architectural and security constraints established in Phase D8.1:
- **Zero Public Exposure:** Jenkins HTTP is bound exclusively to host loopback (`127.0.0.1:8080`).
- **Zero Daemon Privilege:** The Docker socket (`/var/run/docker.sock`) is not mounted. The container runs with `privileged: false`, `cap_drop: [ALL]`, and `no-new-privileges: true`.
- **Decoupled Architecture:** Jenkins configuration and storage exist completely outside the DocVault application repository in `/home/docvault/docvault-jenkins/` with restrictive `0700` permissions.
- **Dedicated Persistence:** State is maintained in a dedicated named Docker volume (`docvault_jenkins_home`).
- **Application Stack Protection:** Pre- and post-installation audits confirm DocVault application containers (`docvault-api-1`, `docvault-postgres-1`) remained continuously healthy and completely unaffected.

### 4.1 Network Security Verification
- **Host Port Binding:** `127.0.0.1:8080` verified via `ss -tulpn`. The port is bound exclusively to the loopback interface (`lo`). No interfaces on `0.0.0.0` or `10.0.2.15` listen on port 8080.

## 6. Secure Administrator Setup Instructions

The Jenkins setup wizard remains enabled as mandated by least-privilege security controls. The administrator must complete initial onboarding through the private loopback interface.

### Step 1: Establish SSH Tunnel (MobaXterm / Windows Terminal)
From the Windows 11 host, execute:
```bash
ssh -N -L 8080:127.0.0.1:8080 docvault@10.0.2.15
```
*(Alternatively, in MobaXterm: Open **Tunneling** -> **New SSH tunnel** -> Forward local port `8080` to remote server `127.0.0.1` port `8080` through SSH gateway `10.0.2.15` user `docvault`)*.

### Step 2: Retrieve the Initial Unlock Secret
On `docvault-srv`, execute:
```bash
docker exec docvault-jenkins cat /var/jenkins_home/secrets/initialAdminPassword
```
*(Keep this token confidential; do not commit or transmit it)*.

### Step 3: Complete Web Setup Wizard
1. Open a local web browser on Windows 11 and navigate to: `http://localhost:8080`.
2. Paste the unlock secret into the **Unlock Jenkins** screen.
3. Select **Install suggested plugins** (or select standard plugins: Git, Pipeline, Credentials Binding).
4. On the **Create First Admin User** screen:
   - Provide a strong, unique username and password.
   - Do not use default credentials.
5. On the **Instance Configuration** screen:
   - Leave Jenkins URL as `http://127.0.0.1:8080/` or `http://localhost:8080/`.
6. Click **Save and Finish**.

## 7. Rollback Procedure

If the Jenkins controller must be stopped or rolled back, execute the dedicated Compose down command:

### 7.1 Non-Destructive Service Shutdown (Preserves Configuration)
```bash
cd /home/docvault/docvault-jenkins
docker compose -p docvault-jenkins down
```
*This removes the `docvault-jenkins` container and network while preserving the `docvault_jenkins_home` persistent volume and all setup configuration.*

### 7.2 Complete Removal (Administrator Intentional Deletion Only)
If the administrator explicitly chooses to delete all Jenkins data:
```bash
cd /home/docvault/docvault-jenkins
docker compose -p docvault-jenkins down -v
rm -rf /home/docvault/docvault-jenkins
```
> [!CAUTION]
> Never run `docker system prune` or remove DocVault volumes (`docvault_postgres_data`, `docvault_documents_data`).
